## Unreleased

- `close resolved`, `close duplicate`, `close stale`, `close deprecated`: the checks, each with evidence classes as subcommands and the `--apply` / `--apply-with-ai` / `--apply-with-ai-auto` modes
- `close resolved landed`: what the PR's diff adds is already in the provider source, or what it deletes is gone, arrived after the PR opened; `git log -S` names the commit
- `close deprecated` matches removed and deprecated properties against the PR's diff, prose as the fallback
- `close stale` no longer has a `conflicted` class; conflicts are not abandonment
- `close report`: `report/close-<yyyymmdd-hhmm>.html`, every candidate of every check with linked evidence, dark mode; `--with-ai` scores them all
- `fetch` stores each open PR's diff (`diffs` table)
- `label bug`, `label enhancement`: add-only labellers
- `PRAWN_SRC_DIR` for the provider checkout; `--src-dir` on `close resolved`, `close deprecated`, `close report`
- `reopen`, `cache`, `stats`
- `explore`: one self-contained html page over every PR open at any point since `--since` / `PRAWN_SINCE` — a global filter bar (period, state, group, author, service, kind, label, court, effort, and a query language) above the tabs: the data (every matching PR by court, effort, age, idle, rounds, first response, AI score, with each PR's life bar and timeline), the trends (tfpp's model: a tree of metrics over the filtered set, presets, panels that combine by drag and drop, stack, split, a right axis for a second unit, `% change`), the suggested (the easy wins by category: approved but unmerged, docs-only, tests-only, dependency bumps, small fixes and enhancements in the maintainers' court, re-reviews, unanswered, likely closes; each a `suggested:<name>` query on the data tab; **by service** regroups the small PRs in the maintainers' court by service), the people (authors with merge rate and trend, reviewers with load and response), the areas (services, kinds of change, labels), and the checks (every close candidate, restricted to the filter)
- `explore` data tab: the columns are configurable — drag a header to reorder, × on a header removes it, **columns** adds any field collected on a PR (the review roll, CI, dates, decision, milestone, waiting, resolve time, closes, checks... ~45 of them); the order lives in the url (`dc=`) so saved views, download, upload, paste, and the AI prompt cover the table as they do the trends
- `explore` collects what [ghp-sync](https://github.com/katbyte/ghp-sync) stamps on a project: **reviewed by**, **approved by**, **changes requested by** with request and review-comment counts (`kat(×2 ✎10)`), review comment totals, a **status** (merged, closed, or an open PR's state today), and **ci** (the head commit's checks: passing, failing, running); every `fetch` refreshes mergeability and CI across the open set in its reconcile walk, since neither moves a PR's updated time; query keys `reviewedby approvedby changesby status ci reviewcomments`
- `explore` trends: **quality by group** — member reviews, review comments, and changes-requested rounds per PR, and the share merged clean, by the author's group and the month the PR opened (resolved PRs only); **review load by group** — the same member work by the month it was left; presets for each, and a **partners: member work** preset — member reviews, review comments, and comments on the partner group's PRs by month, as lines and as stacked bars; `member reviews` and `member ✎` data columns and `memberreviews memberreviewcomments membercomments` query keys
- `explore --serve <port|host:port>`: after writing the page, serve it until ctrl-c and print the addresses other machines on the network can open it on; the page is written beside its path and swapped in whole, so a page being served is never read half-written; every request is logged with the viewer's login when a login-aware proxy in front sets it (`X-Forwarded-User` and friends), the client address, path, status, size and time; the served page gets a **refresh** button in place of copy link, which has the server sync with github and rebuild (one at a time, whoever asked) and reloads when it is done; while it runs the button reads refreshing…, and a click on it opens a window showing what the server is printing, live, with its retries and rate-limit waits. `--serve` no longer waits on github before it serves: the page goes up at once from what the database holds and the sync runs behind it as the first refresh
- `explore`: the tabs moved into the header as a dropdown where the page's name was, and two are renamed — **data** is **prs**, **areas** is **services** (old links and saved views still open); the view chips are a **filter** dropdown that ticks as many as apply (the same key across two means either, different keys both; the query box shows the merged result), with shorter names a **mergeable** entry beside conflicted, and new **ci failing**, **ci not run** and **ci expired** entries (an open PR whose head commit has no checks is not run when the commit is recent and expired when it is over 400 days old, which is when github drops check results; the ci grouping, column and PR detail name both), which puts the saved-view controls on the same line — now just **save** (asks for the name, the selected view's by default, and can also write a file), **upload**, **delete** and **ai** (which takes the AI's answer back itself), each tab's stat tiles sit above its controls, **clear** goes back to every open PR where it used to show every state, and the PR detail's review line shows the head commit's ci; the saved-view controls show on every tab, since a view is the filter every tab shares plus the prs columns and the trend panels; a three-state **draft** button beside the states — off hides drafts, lit shows them with the rest, purple shows only them (`dr=yes|no`); the prs tab's **group by** (`gb=`) puts the table in sections — suggested category (docs only, tests and ci only, dependency bumps, small fixes…), kind of change, service, court, status today, ci, author group, effort, author — each keeping the sort inside it, each folding shut on a click of its header (**fold all** / **unfold all** beside the select; `gc=`); **show** beside it narrows the table to one kind of PR — approved, docs only, ci/test only, a single property, 2–4 properties (`sh=`)
- `explore` kinds of change: **examples** (`examples/`) and **contributing** (the contributor guide, `contributing/`) are kinds of their own, apart from **docs** (the provider's, `website/`), and `.changelog/` entries count as changelog where they were "other"; the suggested tab and the suggested grouping split docs into provider docs only, examples only, and contributing docs only, **show** offers each, a **documentation** grouping sections the docs-only PRs by which of the three they are, and the filter list has **examples** and **contributing docs**
- teamcity: with `TC_SERVER`, `TC_TOKEN` and `TC_PROJECT` set, `fetch` also collects the acceptance test builds teamcity ran on pull request branches (`tc_builds` table; every build it keeps the first time, those since the last sync after) and names the failed tests of each open PR's latest failing builds. `explore` shows a **tests** row in a PR's detail — the outcome, the counts, each service's build as a link, how long ago, the commits pushed since, the tests that failed — with **tests**, **tests failed**, **tests passed**, **test age** and **since tests** columns, `tests testsfailed testage testsince failedtest tested` query keys, a **tests** grouping, and filters for tests failing, tests passed with nothing pushed since, and never tested. Read-only: prawn never starts a build. Without the three settings nothing changes
- `fetch`: mergeability is asked for again where github answered UNKNOWN — it works it out on the first ask after the base branch moves and answers on the next, so one ask left most of the open set unknown and the conflicted and mergeable filters undercounting
- `explore` **kind**: each open PR is one kind of change, the first that fits, biggest first — resources added, 1 resource added, data sources added, data source added, list resource added, api version upgrade, state migration, refactor, property removed, deprecation, properties added (1, 2-4, 5+), properties changed (1, 2-4, 5+), test fix, documentation, ci / tooling and dependencies, bug fix, other — read from its diff, files, title and labels. It replaces the "kind of change" grouping (which only listed file types) and takes in the "properties changed" one; there is a **kind** column and `kind:` query key (`kind:"1 property"`). The filter bar's file-type picker is now **files**, its query key `touches:` (`kind:docs` no longer means files)
- `explore --serve`: a **db** button beside refresh downloads the server's database (a whole, consistent copy, named with the day: `prs.20261005.db`) or uploads one in its place — how a database fetched on one machine gets into a container without walking the whole repo again. An upload is checked before anything is touched (sqlite, sound, a prawn database no newer than the server), the database it replaces is kept beside it as `prs.db.replaced`, and the page is rebuilt from it without syncing, watched in the refresh window; refused while a refresh runs
- `explore` prs tab: the group by, show and filter dropdowns list their choices alphabetically; the "status today" grouping is just "status"
- `fetch gh` and `fetch tc`: either source alone; `fetch` does both
- `fetch`: a page of updated PRs github cannot assemble (one with an enormous timeline in it) no longer stops every sync at the same spot; after two tries the sync carries on a PR at a time, where waiting out seven retries first cost eight minutes a sync
- ci **needs approval**: a fork's workflows wait for a maintainer to approve and run them, and the two or three jobs that run anyway (triage, labellers) made such a PR read "passing"; `fetch` now counts the held workflows on each head commit and `explore` shows the state in the ci column, row, grouping and filter list (`ci:approval`)
- `explore` prs tab: opens sorted by a new **updated** column, the most recently changed first; the "priority" sort is gone from the list (it still breaks ties, and old links that name it open on the new default); a small arrow beside the sort select reverses the order, and **clear** puts the sort back with the filters
- ci in depth: every `fetch` now measures, for each open PR, when its checks last ran, which checks fail (helper jobs left out), since when it has been failing (kept across pushes that fail again), how many commits behind its base branch it is, and how many commits the base has had since the checks ran (`pr_ci` table, a few dozen requests a fetch). `explore` shows them as a **ci** row in a PR's detail, slanted red stripes over its life bar for as long as ci has been failing (blocked is orange now, leaving red to ci), **ci age**, **failing for**, **failing checks**, **behind** and **ci drift** columns, `ciage failingfor failing behind drift` query keys, and a **failing check** grouping
- `explore` prs tab: **open** opens every PR in the table in a new tab, the folded groups left out, asking first past 25 and saying so when the browser blocks them
- `explore` prs tab: **export** opens a dialog of the columns to write, the table's own checked and in its order, dragged into any other — a csv download, a copy that pastes into a spreadsheet, a markdown list that pastes formatted into slack or github, or the PR numbers alone; every matching row (or, with **only shown**, just the groups that are not folded), in the table's sort and grouping, with labels, services and reviewers in full, and the PR numbers as links (a `HYPERLINK` formula in the csv, real links in the copy)
- `explore` reads each open PR's stored diff for the schema properties it adds or changes on existing resources (schema keys, model tags, docs bullets): a **props** column, `props` and `prop:<name>` query keys, the names in the PR detail, and the single-property and 2–4-property kinds above
- `fetch`: a later timeline page holding something the token can't read (a review request to a team, without org access) no longer fails the run; the node is left empty, as the first page already did
- a container (`dockerfile`, `docker-compose.yml`, `make docker`): serves the explore page and refreshes it on a cron schedule (`EXPLORE_CRON`), reading the same `.prawn` file the cli does; the release workflow publishes it to `ghcr.io/katbyte/prawn`, signed with cosign and attested
- the standard katbyte tooling, as tctest and terrafmt: CI workflows (build, tests, golangci-lint with azproviderlint, depscheck, govulncheck, CodeQL, actionlint, yamllint, shellcheck, typos), dependabot, goreleaser releases with cosign signing and SLSA provenance, a homebrew tap formula, dev tools pinned in `.tools/go.mod` and built by `make tools`, `SECURITY.md`, `CODE_OF_CONDUCT.md`; the stricter linters cleaned up (`slices.Sort`, unused receivers, `fmt.Fprint`)
- `fetch --since`: backfills every PR closed or merged since the date in month windows, resumable, and stores every PR's full timeline (`events`, `commits` tables) with `merged_by`, `milestone`, `base_ref`, `head_ref`; long timelines page to completion
