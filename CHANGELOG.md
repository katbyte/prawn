## Unreleased

- `close resolved`, `close duplicate`, `close stale`, `close deprecated`: the checks, each with evidence classes as subcommands and the `--apply` / `--apply-with-ai` / `--apply-with-ai-auto` modes
- `close resolved landed`: what the PR's diff adds is already in the provider source, or what it deletes is gone, arrived after the PR opened; `git log -S` names the commit
- `close deprecated` matches removed and deprecated properties against the PR's diff, prose as the fallback
- `close stale` no longer has a `conflicted` class; conflicts are not abandonment
- `close report`: `report/close-<yyyymmdd-hhmm>.html`, every candidate of every check with linked evidence, dark mode; `--with-ai` scores them all
- `fetch` stores each open PR's diff (`diffs` table)
- `label bug`, `label enhancement`: add-only labellers
- `PRAWN_SRC_DIR` for the provider checkout; `--src-dir` on `close resolved`, `close deprecated`, `close report`
- `reopen`, `cache`, `stats`
- `explore`: one self-contained html page over every PR open at any point since `--since` / `PRAWN_SINCE` — a global filter bar (period, state, group, author, service, kind, label, court, effort, and a query language) above the tabs: the data (every matching PR by court, effort, age, idle, rounds, first response, AI score, with each PR's life bar and timeline), the trends (tfpp's model: a tree of metrics over the filtered set, presets, panels that combine by drag and drop, stack, split, a right axis for a second unit, `% change`), the suggested (the easy wins by category: approved but unmerged, docs-only, tests-only, dependency bumps, small fixes and enhancements in the maintainers' court, re-reviews, unanswered, likely closes; each a `suggested:<name>` query on the data tab; **by service** regroups the small PRs in the maintainers' court by service), the people (authors with merge rate and trend, reviewers with load and response), the areas (services, kinds of change, labels), and the checks (every close candidate, restricted to the filter)
- `explore` data tab: the columns are configurable — drag a header to reorder, × on a header removes it, **columns** adds any field collected on a PR (the review roll, CI, dates, decision, milestone, waiting, resolve time, closes, checks... ~45 of them); the order lives in the url (`dc=`) so saved views, download, upload, paste, and the AI prompt cover the table as they do the trends
- `explore` collects what [ghp-sync](https://github.com/katbyte/ghp-sync) stamps on a project: **reviewed by**, **approved by**, **changes requested by** with request and review-comment counts (`kat(×2 ✎10)`), review comment totals, a **status** (merged, closed, or an open PR's state today), and **ci** (the head commit's checks: passing, failing, running); every `fetch` refreshes mergeability and CI across the open set in its reconcile walk, since neither moves a PR's updated time; query keys `reviewedby approvedby changesby status ci reviewcomments`
- `explore` trends: **quality by group** — member reviews, review comments, and changes-requested rounds per PR, and the share merged clean, by the author's group and the month the PR opened (resolved PRs only); **review load by group** — the same member work by the month it was left; presets for each, and a **partners: member work** preset — member reviews, review comments, and comments on the partner group's PRs by month, as lines and as stacked bars; `member reviews` and `member ✎` data columns and `memberreviews memberreviewcomments membercomments` query keys
- `explore --serve <port|host:port>`: after writing the page, serve it until ctrl-c and print the addresses other machines on the network can open it on; the page is written beside its path and swapped in whole, so a page being served is never read half-written; every request is logged with the viewer's login when a login-aware proxy in front sets it (`X-Forwarded-User` and friends), the client address, path, status, size and time; the served page gets a **refresh** button in place of copy link, which has the server sync with github and rebuild (one at a time, whoever asked) and reloads when it is done
- `explore`: the tabs moved into the header as a dropdown where the page's name was, and two are renamed — **data** is **prs**, **areas** is **services** (old links and saved views still open); the view chips are a **filter** dropdown that ticks as many as apply (the same key across two means either, different keys both; the query box shows the merged result), with shorter names and new **ci failing** and **ci not run** entries (an open PR whose head commit has no checks; the ci grouping, column and PR detail name it too), which puts the saved-view controls on the same line — now just **save** (asks for the name, the selected view's by default, and can also write a file), **upload**, **delete** and **ai** (which takes the AI's answer back itself), each tab's stat tiles sit above its controls, **clear** goes back to every open PR where it used to show every state, and the PR detail's review line shows the head commit's ci; the saved-view controls show on every tab, since a view is the filter every tab shares plus the prs columns and the trend panels; a **draft** toggle beside the states, on for drafts only (`dr=yes`); the prs tab's **group by** (`gb=`) puts the table in sections — suggested category (docs only, tests and ci only, dependency bumps, small fixes…), kind of change, service, court, status today, ci, author group, effort, author — each keeping the sort inside it, each folding shut on a click of its header (**fold all** / **open all** beside the select; `gc=`); **show** beside it narrows the table to one kind of PR — approved, docs only, ci/test only, a single property, 2–4 properties (`sh=`)
- `explore` prs tab: **open** opens every PR in the table in a new tab, the folded groups left out, asking first past 25 and saying so when the browser blocks them
- `explore` prs tab: **export** opens a dialog of the columns to write, the table's own checked and in its order, dragged into any other — a csv download, a copy that pastes into a spreadsheet, a markdown list that pastes formatted into slack or github, or the PR numbers alone; every matching row, in the table's sort and grouping, with labels, services and reviewers in full, and the PR numbers as links (a `HYPERLINK` formula in the csv, real links in the copy)
- `explore` reads each open PR's stored diff for the schema properties it adds or changes on existing resources (schema keys, model tags, docs bullets): a **props** column, `props` and `prop:<name>` query keys, the names in the PR detail, and the single-property and 2–4-property kinds above
- `fetch`: a later timeline page holding something the token can't read (a review request to a team, without org access) no longer fails the run; the node is left empty, as the first page already did
- a container (`dockerfile`, `docker-compose.yml`, `make docker`): serves the explore page and refreshes it on a cron schedule (`EXPLORE_CRON`), reading the same `.prawn` file the cli does; the release workflow publishes it to `ghcr.io/katbyte/prawn`, signed with cosign and attested
- the standard katbyte tooling, as tctest and terrafmt: CI workflows (build, tests, golangci-lint with azproviderlint, depscheck, govulncheck, CodeQL, actionlint, yamllint, shellcheck, typos), dependabot, goreleaser releases with cosign signing and SLSA provenance, a homebrew tap formula, dev tools pinned in `.tools/go.mod` and built by `make tools`, `SECURITY.md`, `CODE_OF_CONDUCT.md`; the stricter linters cleaned up (`slices.Sort`, unused receivers, `fmt.Fprint`)
- `fetch --since`: backfills every PR closed or merged since the date in month windows, resumable, and stores every PR's full timeline (`events`, `commits` tables) with `merged_by`, `milestone`, `base_ref`, `head_ref`; long timelines page to completion
- `PRAWN_GROUP_<name>=login,login`: named groups of authors for the explore page, from the environment or `.prawn`; `PRAWN_MAINTAINERS` names the group that counts as maintainers (default `members`)
